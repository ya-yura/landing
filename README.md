# Посадочная под заявку

Премиальный русскоязычный статический лендинг услуги создания отдельной посадочной страницы под один конкретный путь клиента.

## Локальный запуск

Проект не требует сборщика и зависимостей. Запустите любой статический сервер из этой папки, например:

```powershell
py -m http.server 4173
```

Откройте <http://localhost:4173/>.

## Структура

- `index.html` — семантическая разметка лендинга и каталог публичных примеров.
- `styles.css` — адаптивная стилизация, состояния фокуса и reduced motion.
- `script.js` — мобильное меню, интерактивные маршруты, форма с mailto-fallback, фильтры с синхронизацией URL, события Метрики и scroll-reveal.
- `favicon.svg`, `og-cover.svg` — favicon и Open Graph-обложка.
- `robots.txt`, `sitemap.xml` — базовая SEO-настройка.
- `.github/workflows/pages.yml` — workflow публикации для резервного репозитория и отправки короткой версии в ветку `gh-pages`.

## Публикация

Репозиторий `landing` публикуется GitHub Actions в ветку `gh-pages`, откуда GitHub Pages отдаёт статический сайт. Резервный репозиторий `landing-path-20260812` публикуется официальным workflow из `.github/workflows/pages.yml`.

- Репозиторий: <https://github.com/ya-yura/landing>.
- Демо: <https://ya-yura.github.io/landing/>.
- Совместимый старый адрес: <https://ya-yura.github.io/landing-path-20260812/>.

Короткий маршрут публикуется из отдельного репозитория `landing`; исходный репозиторий сохранён как резервный совместимый адрес.

## Проверенные материалы

В каталог включены публичные страницы из брифа. На момент проверки все 18 URL ответили `200 OK`; у ранее использовавшихся страниц заголовки считаны с самих страниц. По умолчанию видны 8 наиболее релевантных посадочных страниц, остальные открываются фильтрами или кнопкой «Показать все примеры». Визуальные карточки используют нейтральные интерфейсные фрагменты и не приписывают страницам коммерческие показатели.

Основной канал связи — `mailto:sharikov@gmail.com` с темой «Посадочная страница под услугу» и полями для содержательного описания задачи.

Короткий адрес без завершающего слеша также отвечает успешно: <https://ya-yura.github.io/landing>.

## Аналитика

Использован существующий счётчик Яндекс Метрики `111469697` («Portfolio github»), уже привязанный в кабинете к `ya-yura.github.io`. Новый счётчик не создавался. Код счётчика установлен один раз в `index.html`; дублирования в `script.js` нет.

Созданы JS-цели: `landing_cta_click` (ID `596197608`) с параметрами `location=header|hero|final` и `cta=describe_task`, `landing_mailto_click` (ID `596198216`) с местом клика, `landing_form_submit` (ID `596198315`, только после подтверждённого ответа endpoint), `landing_portfolio_open` (ID `596198316`) с параметром `project`, `landing_portfolio_expand` (ID `596198381`) с `expanded=true|false`, `landing_portfolio_filter` (ID `596198389`) с параметром `category`. Дополнительно сохранены технические события интерактивности и глубины просмотра. Клик по mailto считается намерением открыть письмо, а не отправленной заявкой.

Проверка публикации счётчика выполнена через публичный HTML и загрузку `https://mc.yandex.ru/metrika/tag.js?id=111469697`. В кабинете Метрики адрес счётчика подтверждён как `ya-yura.github.io`; все шесть целей отображаются в списке с указанными ID и идентификаторами. Достижения целей не выдаются за фактически собранные данные без отдельного тестового визита: открытие письма, отправка письма, ответ клиента и оплата остаются неподтверждёнными.

## Форма и fallback

Форма «Описать задачу» добавлена в финальный блок. Подтверждённого backend, CRM или endpoint в проекте нет, поэтому случайный внешний сервис не подключался. Сейчас форма валидирует обязательные поля, формирует письмо на `sharikov@gmail.com` и открывает почтовый клиент; сообщение об успешной серверной отправке не показывается. `landing_form_submit` не вызывается, пока не будет настроен и проверен реальный endpoint. Ошибка будущего endpoint переводит пользователя к резервному mailto-каналу.

## UTM-правила

Канонические ссылки и ссылки на примеры остаются без UTM. Для кампаний используются только обезличенные идентификаторы:

- Клиентское письмо: `https://ya-yura.github.io/landing/?utm_source=email&utm_medium=outreach&utm_campaign=landing-2026&utm_content=LEAD_ID`.
- Партнёрское письмо: `https://ya-yura.github.io/landing/?utm_source=email&utm_medium=partner&utm_campaign=landing-2026&utm_content=PARTNER_ID`.
- Реклама: `https://ya-yura.github.io/landing/?utm_source=yandex&utm_medium=cpc&utm_campaign=landing-2026&utm_content=SEGMENT`.

В UTM нельзя помещать имя, email или телефон. Метки не меняют canonical и не мешают фильтрам каталога: фильтр использует только параметр `category`.

## Допущения и ограничения

- Сроки, результаты, конверсия, лиды и окупаемость не обещаются.
- В карточках проектов сохранены названия и описания из брифа; они показывают тип маршрута или интерфейса, а не подтверждённые бизнес-результаты.
- Страница рассчитана на GitHub Pages и не содержит backend. Основной CTA открывает почтовый клиент пользователя.
- Полноценная серверная форма и CRM-связка пока не подключены; Lead ID, UTM, квалификация, статус предложения, ответ клиента и подтверждённая оплата требуют ручной фиксации в CRM или таблице.
- Не добавлены телефон, WhatsApp, отзывы, клиенты, метрики, гарантии, сроки и порядок оплаты: подтверждённых данных для них нет.
